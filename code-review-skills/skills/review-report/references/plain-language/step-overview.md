# 多步骤截图总览：红圈重点，红箭头串联

## 何时使用

向产品、测试、运营说明连续操作、复现路径或状态流转，且已有对应真实截图时，默认先交付一张总览大图，放在报告前部；逐步截图和视频保留在后面供放大与核验。用户明确指定其他形式时从其要求。

要保护的是：读者在同一视野能找到每步在哪里操作、看到什么结果、接着去哪里，无需在多张图之间自行拼接顺序。

单一步骤或单个异常不额外拼大图；截图缺失就标待补，不能用重绘界面补成真实流程。复杂分支无法保持清晰时拆分子流程或使用流程图，不强行排成一条成功路线。

## 最小制作步骤

1. 按真实用户路径挑选截图，先核对步骤、环境、时点和结果是否属于同一旅程；混用不同运行的图片须显式说明，不能声称连续完成。
2. 每步使用连续编号、短标题，以及一句操作或可观察结果。编号按业务顺序，不依赖读者猜测排版方向。
3. 每张截图用红圈或红框突出 1–3 个关键位置，如入口、按钮、弹窗、价格、前后数值、成功或失败提示；标注不能压住关键文字，不只圈整页。
4. 用红箭头连接步骤卡片。优先把箭头放在卡片外的留白处，箭头终点明确落到下一步；长流程换行可用蛇形排列并标明阅读方向，避免连线穿过截图或交叉。
5. 箭头只表达图中已说明的步骤转移，不自动证明点击生效、接口成功或因果。存在等待、人工介入或失败分支时明确标注，不把异步过程画成无条件成功。
6. 顶部说明流程主题及必要环境，末尾保留待确认项；结果必须与图上实际数值一致。例如“收到成功提示”和“资产数值已更新”需分别判断。
7. 输出可直接打开、放大的单张图片；原图单独保留，标注与布局使用可编辑叠层或制作源。按用户指定渠道放在正文首图或同条消息中；发送仍服从该渠道授权。

## 验收检查卡

- **顺序**：编号完整且不重复，线性流程中相邻步骤均有方向明确的连接；分支单独写出条件，阅读方向与布局一致。
- **对齐**：圈选对应真实关键控件或结果，箭头不遮挡截图、文字或其他连线；没有为了排版改写页面和数值。
- **可读**：整体能看懂路径，放大能读出关键文案和数值；缩略图也能辨认步骤标题、编号和方向。不为塞进一张图把内容缩到无法阅读。
- **证据**：每条结果都有对应截图或明确的待确认标记。截图不替代连续交互视频、服务端回执或到账核验；图像美观不升级证据等级。
- **交付**：文档回读确认总览在逐步详情之前；渠道需要图片时发送实际图片，不能只提供制作脚本或文件名。

## 不固定为通用要求

不固定步骤数、四列布局、蛇形排列、输出尺寸或视频时长。它们由当前流程、阅读渠道和用户要求决定；总览图不自动增加录屏、重测、后台写入或发送授权。
