# 报告验收

交付前读取，检查对应风险；不要给无关局部任务追加业务测试或设备操作。测试默认跳过审查：仅核对文件路径、同基线同范围的新增/删除行数与合计，并明确标示；下文逐文件/块审查、风险评分、关系覆盖与完整 patch 要求仅针对纳入审查的非测试文件。用户明确要求审查指定测试时除外。

- 新版先完成全部文件/hunk的实质审查并校验，再人工提炼重点层；完整逐项审查默认收起但内容不减，仍以修复/需求关系→按冻结提交顺序的阶段→文件及 diff 分析；关系及阶段均标“修复”或“需求”，给出当前状态，完整审查展开后相关业务/辅助文件和块在本条下展开，测试仅列改动行数。每组文件与块保持危险系数降序，不用另一个 commit 代码大列表代替就近展示。
- R 编号与 commit 数明确区分，允许多对多关系及仅一个阶段的独立需求；起因在基线时注明来源。全部冻结 commit、文件和块均有覆盖，重复跨关系展示不改变净统计；不存在的 commit/file 引用、乱序或漏覆盖必须拒绝，不能从 subject 自动猜关系或把旧问题当当前未修复。
- 风险理由逐项绑定冻结改动与实际消费者；模型说明可追溯 Google 审查规范、Microsoft 变更量/依赖研究及 ISTQB 风险原则。不能将自定权重说成行业标准或概率，不以路径/关键词机械生成语义分；评分算术与文件最高块聚合经过检查。
- 页面及导航没有“审查依据与交付边界”或同义过程总述，不通过折叠、改名或附录保留整块。内部约束、采集与证据记录仍完整；影响判断的限制就近简述，影响整体结论的必要限制仅在结论一句话说明。
- 审查对象、HEAD/base/target、dirty 三层与时间明确；当前报告与快照指纹一致。输出文件位于仓外，业务源码和 Git 状态保持原样。
- 页首统计与基线/目标已合为一个简短概览，仅默认展示当前分支、目标分支、commit 数及增删行数；不重复铺长基线卡。完整 SHA、路径、共同祖先、时间/指纹与三层状态等审计信息仍可从默认折叠详情找到；文件分类/代码块统计留在各自区域，不删数据或改统计口径。
- 确认问题主卡接在结论与业务主线之后，位于完整审查折叠层之外，先于commit/文件diff和长表；同一主卡说明用户表现、影响、触发条件、证据状态、复现与实际/预期，最小关键证据直接可见，按严重度优先、同级参考危险系数。确认度与运行验证状态独立标明，疑似不冒充确认，代码/测试不冒充模拟器实锤；无确认问题不生成空问题区。
- 页面与导航不出现“本轮实际验证”“当前 HEAD 执行结果”及同义的独立验证汇总表，不改名、折叠或搬到附录保留。内部验证数据与原始证据仍完整；必要结果及未验证边界只在对应问题、文件或代码块旁简述，不因此停止实际验证或隐藏有 diff 的测试文件。
- 页面及导航没有“先辨清两种差异”过程说明或重复的修复/撤回、提交演变总表；修复/需求主条目必须保留并在下面直接展示代码，不得套用旧的删总表要求隐藏它们，也不能只放跳转链接让读者去别处拼接。
- 没有路径/旧路径搜索、类型下拉、只看关联问题等文件筛选及其计数/无匹配提示；各范围文件仍完整列出。展开/收起、代码换行和证据跳转可正常使用，内部分类与问题关联数据保持完整。
- 多个独立目标按 1、2、3 有序列表逐项换行；单目标及旧版单目标字符串正常显示，目标文本仍做 HTML 转义；不靠标点自动猜测目标边界。
- 全部纳入审查的文件覆盖，人工确认业务/测试/配置等分类；测试仅保留行数统计。旧/新总行数、增删行和 Git diff 逐项一致；binary 为未知，rename/mode 元信息完整，untracked 实际内容纳入。
- 业务、辅助审查与测试行数使用独立区域和文件清单，业务在前，测试统计在后。测试只列路径、增删行数及合计，明确标“跳过审查”；无测试源码、逐块分析、危险系数、必要性或覆盖评价。业务审查统计不得混入测试并声称全部已审，行数统计不能当作测试通过。
- 当前commit/范围没有实际diff的文件分区整块不显示，不残留标题、0值统计、“本范围无此类改动”提示或导航；有diff的业务/辅助/测试区域仍保留。不得仅按hunk数量判空，rename/mode-only/binary等真实变化仍须展示。
- hunk 没有漏项或错配；删除、新增、上下文和末尾换行 marker 完整，旧/新行号各按 prefix 累加。全部代码可展开/收起，完整 patch 可复制或下载。
- 每个代码块标题直接显示本 hunk 的实际 `+新增 / -删除 行`，折叠后仍可见；计数不含上下文、header、元信息或缺换行 marker。大段修改标题有 `⚠️ 大段改动` 提醒；不以文件总行数代替该块改动量，不把预警当成缺陷或 P? 优先级。
- 文件层原“改动用途 / 为什么要改 / 不改动有什么影响”已合并为“需求文档中需求描述”；默认是一两句需求摘要，非 hunk 说明拼接长段；来源与原三项说明保留在默认折叠补充中。需求未明确要求（含必要支撑）时合理性理由在折叠区外可见，缺文档明确标缺失，commit 不冒充需求文档。
- 每文件新增独立可见项“是否符合最小必要改动”，有固定结论及简短依据，不能以“必要”或测试通过推导。旧数据缺字段时不伪造正向结论；验证非明确需求缺理由、最小性缺理由及未转义文本会被拒绝或安全展示。
- 每文件、每 hunk 说明必要性、合理性、移除此项的具体影响，目标依据独立于实现；文件层补充默认折叠，hunk 说明继续就近保留。新增 source/ID/上下文等符号解释创建与生命周期；兼容理由有真实消费者依据。
- 从用户视角检查：代码块标题与改动用途能让读者直接对应到用户页面、实际按钮/操作和可观察结果；函数调用链只作机制/证据，不用内部术语冒充用户步骤。内部支撑注明关联场景/用户表现不变；前后差异有基线，未运行的预期效果不写成已实测改善。
- 触及登录、首页 Feed、埋点等关键链路的文件标题与对应代码块标题标红，带 `‼️ 改动 xxx 关键链路，仔细审查` 的具体文案，折叠时也可见。触达有实际变更/执行链依据，不能只按关键词标记；混合文件未触及的块不连带标红，多链路逐项指出；保留增删行数及需要的 `⚠️`，不把预警冒充 finding 或放行结果。
- 每块标题均显示必要性结论；人工确认 `冗余/过度改动` 的块在标题与审查信息区使用黄色背景并带 `⚠️ 非必要`，折叠和 hover 时仍可识别。`有条件必要/证据不足` 不自动升级为确认非必要，其他块不被连带标黄；原始代码红绿、关键链路红字、大段修改警告和全部锚点不变。新增 guard 的说明已核对既有门槛、生产可达路径、返回值实际消费及反事实，不用测试自证必要性。
- 每个文件和独立代码块标题都有危险系数/区间、文字等级和统一绿黄橙红颜色，折叠可见；按 `risk-scoring.md` 同一模型给六维理由及来源，不能只按行数。文件分不低于最高块分，关键链路/公共契约等小改动适用升级下限；未知不默认记0/绿分。评分与确认度、finding优先级及既有标题预警独立，不以低分自动免审或approve。
- 文件标题和对应方法/函数块标题分别有公共/私有/混合或待确认标识，折叠可见，并简要说明共享对象或内部边界。依据导出/public API及实际直接/间接消费者，不只看目录名或export；文件与方法不连带定性，非方法块不强贴方法标签。作用域判断与危险系数影响面一致，“私有”不能遮蔽经公共入口传播的回归风险。
- 滚动展开diff时，对应文件标题区域在其文件范围内吸顶，始终可辨认文件；换文件切换身份，不叠多个旧标题，不遮挡代码/行号/问题锚点，窄屏长路径仍可识别。
- 文件按最终危险系数降序，文件内部代码块也降序；分组内排序明确范围，同分稳定保留原顺序，区间/未评估不伪装低分。呈现排序未改变原始patch、hunk ID、行号、指纹或证据跳转，复制/下载仍是完整原patch。
- 语义表覆盖 F/S/I、必须保护的原行为、边界与 Oracle，不拿测试数量代替用户结果。原生触达时另一端结论有文件与符号依据。
- 每个 P? 调用了 plain-language；用户表现、影响、复现步骤、实际/预期、关键原因、建议独立可读。P? 与真实行/代码块证据双向关联，关键行 focus 高亮和数字标记对应解释；优先级、确认度、频率分开，不外推线上归因。
- 文件“补充风险与验证边界”无需提示风险/关键证据缺口时仅显示“无”，“另一端逻辑是否一致”确认一致时仅显示“一致”；其他结论只补一句精简说明。完整依据保留在内部 `risk_detail`/`pair_detail` 或原始证据，不在这两项重复长段；P? 入口和真实验证缺口不被隐藏，不能把未确认或未核对压成正常结论。
- 正式报告没有待填写占位符。草稿醒目标识未完成，不能冒充正式审查；无 findings 不自动产生“可合并”“无风险”。验证只记录实际结果，缺口单列。
- 设备验证先确认使用者当次指令或当前项目合同已授权，再核对占用、平台、安装包及运行源码身份，同设备只有一个操作方。证据保留已执行条件、版本和实际结果；占用/驱动失败/身份不匹配标受阻或未验证，不能当无法复现。无授权时保留设备验证缺口并继续静态审查；维护 Skill 本身不触发设备操作。
- HTML 以文本转义代码和字段，无外部 CDN/字体/跟踪请求。代码横向滚动只在代码容器内；窄屏正文不溢出，颜色附带文字/符号。
- 用允许的浏览器检查桌面/窄屏、证据跳转/展开收起/换行，并确认不再呈现文件筛选；不可访问则做 HTML 结构、diff 回读与 JS 语法检查，报告视觉验收缺口，不绕过浏览器限制。

维护脚本时执行 `python3 -B scripts/test_report.py` 的隔离 Git 样例，覆盖采集范围、新增/删除/rename/mode/binary、完整 diff 与错误输入拒绝。新版另执行 `python3 -B scripts/test_compact_report.py`，验证关系与提交多对多、阶段顺序和类型、就近代码默认展开及显式纳入测试时的兼容折叠、共享文件的独立锚点、错引用/漏覆盖拒绝，并继续核对删除区块不回流、风险排序不改原patch、评分算术与最高块聚合、静态证据注入保护；JS执行语法检查。源码仓的包内引用校验使用 `npm run validate`，公开内容与示例检查用 `python3 code-review-skills/tests/validate_structure.py`；安装包内仅执行前述 Python 回归即可，无需源码仓的 npm 工程。以上均不证明业务语义或桌面/窄屏视觉正确。

人工/AI分层另按 [focus-review.md](focus-review.md) 核对：未入选重点的全部文件/hunk、各自判断及原始patch仍在HTML中；必要性、正确性、缺依据、重构与历史继承不混称。维护生成器时验证带重点层仍拒绝漏hunk、全patch与锚点不丢、完整外层默认收起及安全清洗，旧输入继续兼容。结构/脚本通过不等于已经逐项完成实质判断或设备验收。

## 人工阅读与交接验收

- 人工区能直接读出整体业务主线、前后差异、测试/通过标准、确认问题、高关注通过项与读者动作；同项主卡不重复，无独立“重点与争议”。✅/❌/⚠️附对象、版本和证据边界，可查技术事实不转交用户判断。
- 确认问题主卡及关键原因的最小源码图不藏在完整审查折叠内；完整AI复核层默认收起且用途明确，全部非测试文件/hunk、patch、行号与风险判断保持。
- 可选内联证据旧输入兼容；PNG/JPEG真实内嵌且离线显示，拒绝外链图片、SVG、畸形base64/签名、脚本/事件属性。源码高亮图与真实diff明确区分。
- 关系头/文件头按真实高度两层避让，下一关系替换旧头；宽图/代码在自身容器内滚动，390px正文无溢出，跳转后关键行不被遮挡。
- 侧会话认可范围、验证层级、仅登记/正文回填/外部同步分别记录；已认可事项不重问，不默认新建聊天或发送。要求飞书交接时按[专属参考](feishu-review-handoff.md)核对本体证据和实际回读，维护Skill本身不触发发送。
