# 埋点代码落地检查表

## 修改前

- 目标仓库、分支和 HEAD 已确认。
- 方案中的事件、属性、类型、枚举、页面和触发条件已冻结。
- 旧事件是否复用、是否需要新增采集点、是否需要业务关联键已有结论。
- 当前工作区 dirty 文件已记录，修改范围已列出。

## 链路核对

按以下顺序回读证据：

```text
用户动作
  -> 同步上下文或快照
  -> 事件预处理
  -> 字段转换
  -> 具体消费者
  -> 投递目标
  -> 最终 payload
```

每个关键字段至少记录逻辑名、最终出网名、提供方、取值时点、实际类型和条件必填规则。事件 ID 只能证明传输身份，不能单独证明业务幂等。

## 输出状态

| 项目 | 结果 | 证据 |
| --- | --- | --- |
| 触发入口 | 已实现、缺失或待核实 | 文件和行号、运行步骤 |
| 字段取值 | 有值、空值、未知或未验证 | 源码和运行载荷 |
| 发送路径 | 目标和转换已核实或未核实 | 消费者、请求或日志 |
| 业务结果 | 客户端反馈或权威终态 | 回调、接口或服务端证据 |
| TEA 收件 | 已核实或待验收 | TEA 查询条件和事件明细 |
