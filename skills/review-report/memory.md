# 可分享的审查案例

这些案例从报告实践提炼，已移除人员、私聊、真实项目代码和原任务身份。它们用于选择审查方法，不能作为当前项目的业务事实或授权。按标签读取相关条目；正反例仅说明方法，当前结论仍需证据。

| 当前信号 | 优先读取 |
| --- | --- |

| 改名、公共层、字段语义、修复回填 | [RR07–RR10](#rr07) |

<a id="rr01"></a>
### RR01 · 同一问题只维护一张主卡

反例：结论、重点与争议、问题详情各抄一遍同一解释。正例：结论一句话指向唯一 P? 主卡，主卡承载原因、证据和动作。边界：历史状态可以保留，不能冒充三个独立发现。

<a id="rr02"></a>
### RR02 · 局部发现不能代替整个分支

反例：只写两个缺陷，读者不知道其他改动要解决什么。正例：先交代整体业务主线、改前改后、测试操作及通过标准，再呈现问题。边界：单个明确问题不硬凑全分支分析。

<a id="rr03"></a>
### RR03 · 标志绑定对象、层级与动作

反例：看到绿色总数就认为所有端到端行为通过。正例：写“✅ 指定版本的代码层核对完成；⚠️ 设备路径待执行，由测试补验”。边界：确认层级和发生频率分开，不能只靠颜色表达。

<a id="rr04"></a>
### RR04 · 关键原因旁直接放关键源码

反例：读者必须跳到长 diff 才能找到因果。正例：问题原因旁展示冻结版本、真实行号和最小源码片段，解释关键行证明什么。边界：源码高亮明确标“非 diff”；同一代码的截图与 patch 不算两次验证。

<a id="rr05"></a>
### RR05 · 人看决策，AI 查全量

反例：先列几处热点，剩余文件套相同句子。正例：先实质审查每个非测试文件和 hunk，再将完整判断及原始 patch 默认折叠，前层只放业务判断、关键证据和动作。边界：折叠不删内容、不减覆盖，材料完整也不自证判断正确。

<a id="rr06"></a>
### RR06 · 滚动时仍知道当前关系与文件

反例：长代码滚动后看不到文件身份，或多层固定标题遮住目标行。正例：关系与文件标题在所属范围吸顶，按实际高度避让并自然接替。边界：必须检查窄屏和跨折叠锚点；样式声明不等于运行验证。

<a id="rr07"></a>
### RR07 · 名称统一不等于功能必要

反例：同一文件里有有效修复，就给顺带改名的 hunk 一并背书。正例：分别确认实例键、业务身份 owner、真实消费者和移除后的失败；无独立贡献判冗余，有作用但超目标判过度改动。边界：只给审查建议，不自动回退或全仓清理。

<a id="rr08"></a>
### RR08 · 视觉大块不等于逻辑迁移

反例：看到大段绿色就认为请求、状态和内容全部重写；或看到只加一层包装就认为无影响。正例：追踪旧新消费者、上下文与副作用，分别解释移动、包裹和真实行为变化。边界：历史阶段出现过的问题不被最终状态抹掉。

<a id="rr09"></a>
### RR09 · 名字、字段 key、值与实验事实分开

反例：旧变量名仍在就断言旧页面身份仍在；共用业务 ID 就推断属于同一实验组。正例：建立最小字段映射并闭合生产者、转换和消费者链，逐断言收口。边界：实验分组必须有实验事实证据；方法见[字段核验](references/field-semantics-evidence.md)。

<a id="rr10"></a>
### RR10 · 修复保留两种比较身份

反例：只贴最终源码绿色高亮就声称修复与分支累计变化都已检查。正例：保留“修复前 → 修复后”和“冻结目标 → 修复后”两份完整业务 diff、双方 hash 与行号。边界：两份 patch 相同也保留比较身份，不外推其他文件。

<a id="rr11"></a>
### RR11 · 启动没有 await 仍可能有同步成本

反例：没有等待网络就断言冷启动零影响。正例：检查调用前缀中的同步读写、队列、上下文准备及通知落地路径。边界：未测量不编造耗时或已发生卡顿，风险信号不自动成为 P0/P1。

<a id="rr12"></a>
### RR12 · 生产者与消费接线分别解释必要性

反例：两个文件都涉及同一 SDK 就认为其一重复。正例：分别说明哪个建立数据、哪个在真实事件路径消费；保留各自反事实。边界：已有生产者已满足输入时优先只扩展消费者，新增同步成本和端到端结果另记。

<a id="rr13"></a>
### RR13 · 只补字段也要查真实发送与时长

反例：只看对象字段就称事件时序和驻留窗口不变。正例：核对已捕获事件、正在计时、排队、持久化、重放和原生上下文如何消费迟到来源。边界：测试总数不跨版本或会话相加；代码与后台收件分别记账。

<a id="rr14"></a>
### RR14 · 测量要主动查闭环与乱序

反例：存在节流就判定不会循环。正例：追踪布局测量 → 状态更新 → 再布局，核对旧回调、异步顺序和驻留重开窗口。边界：已有断言阅读不冒充重跑；持续外部布局变化须单独说明。

<a id="rr15"></a>
### RR15 · 稳定身份可登记，动态入口不能猜

反例：把动态下发的任意入口都写死映射；或一概否定稳定字典。正例：区分稳定页面身份、动态参数和兜底 owner，说明映射的实际消费范围。边界：字典存在不保证所有未来跳链自动正确归因。

<a id="rr16"></a>
### RR16 · 删除名单既查守恒，也查扩张

反例：只证明原列表中的值仍能映射，就称行为完全不变。正例：核对旧集合、替代解析器和新增可接受范围，追到最终事件/资格。边界：映射返回值不自动决定曝光资格，样例测试仅覆盖其实际集合。

<a id="rr17"></a>
### RR17 · 类型、封闭识别与产品顺序分别判断

反例：类型可通过就认为运行时识别和展示顺序均合理。正例：分别核对枚举扩展、动态类别、封闭分支和产品顺序；保留维护耦合成本。边界：功能人审通过不删除工程警讯，也不自动授权改另一端。

<a id="rr18"></a>
### RR18 · 发布状态分层，绑定实际版本

反例：PR 合并、CI 成功或包已出就记设备验收完成。正例：代码、人审、测试、PR/CI、构建、安装、设备/后台、报告回填与外部同步分别记账。边界：构建与新测试提交不同，要先证明生产代码等价再陈述结果。

<a id="rr19"></a>
### RR19 · 外部正文直接承载必要证据

反例：只发一组链接要求读者自行拼接事实。正例：授权内的外部报告直接说明主线、版本、关键证据和动作，真实截图保留来源，规则原文按载体能力折叠。边界：不携带人员私聊、凭据或个人路径；截图只证明它直接支持的事实。

<a id="rr20"></a>
### RR20 · 限定对象自测并回读真实呈现

反例：向本人自测的授权扩成向同事或群发送，API 成功就称图片可见。正例：仅向已授权对象操作，回读正文、附件及折叠交互，按实际阶段写回执。边界：未获授权只交付本地材料，不自动发送、新建会话或扩大接收人。

<a id="rr21"></a>
### RR21 · 人审认可不抹掉旧边界，也不授权修复

反例：解释得到认可后，删掉尚未覆盖的组合条件并自动修改代码。正例：记录认可的对象、基线和层级，保留旧证据缺口；“已登记，正文待回填”与“原报告已更新”分别陈述。边界：修复、设备操作和对外同步依当次授权，不从人审认可推断。
