# 说清楚

## 目标

- 先说明发生了什么、影响谁、如何复现、下一步做什么。
- 涉及多个问题时逐项说明，每项都能独立看懂并独立验证。
- 让结论与代码、日志、数据或图片证据一一对应，不用视觉包装掩盖证据缺口。

## 输出方式

- 在本包内使用 `render_compact_report.py` 统一生成审查报告；以下模板只用于样式与素材参考，问题说明嵌入同一报告。证据片段仅接受静态内容和内嵌 PNG/JPEG；若标注过程使用 SVG 叠层，先导出栅格图再嵌入，不能将 SVG 本体传入片段。
- 默认生成一个可直接打开和转发的单文件 H5 页面；用户明确要求“一句话”“纯文本”或其他格式时服从其要求。
- 生成 H5 前读取 [H5 报告规范](plain-language/h5-report.md)，并基于 [H5 页面模板](../assets/plain-language/h5-report-template.html) 制作，不从空白页重复搭建样式。
- 使用内联 CSS；不依赖 CDN、远程字体或远程脚本。需要携带本地图片时优先嵌入 data URL，确保页面单文件可移交。
- 用户指定输出路径时写到指定位置；未指定时使用宿主提供的 artifact/visualization 目录，并返回可点击的绝对路径。
- 交付前删除所有模板占位符和未使用模块，并打开页面检查桌面与窄屏布局。
- 讲解由真实截图组成的连续多步骤流程时，默认先给一张总览大图：红圈标关键操作或结果，红箭头连接带编号的步骤，再保留逐步详情。制作与验收按[多步骤截图总览](plain-language/step-overview.md)；单步问题、缺少截图或复杂分支不机械套用。

## 内容结构

规范治理、多类问题归纳或共同决策场景先讲清目标、分类原则、问题类型与关键取舍，再按需组织下列内容；同因同处理的情况合并表达，保留可追溯明细。明确修复或单个问题仍直接使用原流程，不额外要求用户确认原则；呈现格式沿用上方约定及用户要求。

1. **结论**：一句业务化判断，并标出对应证据编号。
2. **问题清单**：有几个问题就分几项；每项必须包含：
   - **问题**：从用户视角说明在哪里、做什么时、看到了什么异常。
   - **影响**：哪些用户或业务场景会受影响。
   - **复现路径**：依次写清前提、用户操作步骤、实际结果和预期结果。
   - **原因**：只解释理解该问题所需的关键机制。
   - **确认状态**：说明是运行实锤、代码实锤、代码推演还是待确认。
3. **证据**：每条关键判断关联 `E1`、`E2` 等证据编号，说明来源、关键点和它能证明什么。
4. **建议**：逐项给出下一步动作、验证方式和责任边界。

如果内容不涉及具体问题，省略“问题清单”，沿用“结论 / 影响 / 原因 / 证据 / 建议”。

## 证据与标注

- 用于对外数据结论时，先核对当前代码口径及真实数据回执；缺任一侧证据则保留缺口。外部读取与发送均服从当次授权。
- 代码证据必须显示文件路径和真实行号，只截取理解结论所需的上下文；对关键行使用背景高亮、边框和编号标记，并在旁边解释该行证明什么。
- 图片证据必须使用真实截图或用户提供的图片；用 SVG 叠层的圆、框、箭头和编号圈选关键区域，编号与右侧说明一致，不遮挡关键信息。
- 每个证据块优先标记 1–3 个关键点。不能仅靠颜色传意，同时使用编号、文字和足够对比度。
- 复现路径只写用户可执行、可观察的页面入口、操作和结果；代码调用链放在证据中，不代替用户步骤。
- 只有静态代码证据时，明确写“以下为代码推演路径，设备运行态未验证”；频率不清楚时写“频率待确认”。
- 暂时没有可靠代码、日志或图片时，直接标记“证据待补充”，说明缺什么和最小验证方法，不编造素材。

### 多来源截图对照

- 需要在一张图里比较多个页面上的同类字段时，将真实截图按来源或资料用途并列展示。每块标明页面和资料用途，保留核对所需的区分标识、时点和字段标签，只圈关键字段及其值。编号帮助读者找到对应截图，流程箭头用于实际有先后关系的步骤。
- 有原件缺失时，在正文就近写清已核实的差异、待补的材料及所需字段。图注只写各张截图直接支持的事实。交付前检查手机上能否辨认来源和关键值。

## 交付检查

- 检查每条结论至少关联一条证据，或明确标为待确认。标题、首屏结论、正文和图注使用一致的确认度，用户转述、间接证据或条件判断在结论出现的位置注明来源与范围。
- 检查代码路径、行号、图片来源和标注位置与原始材料一致。
- 检查 HTML 可离线打开、窄屏不横向溢出、标注随图片缩放保持对齐。
- 检查并移除 token、cookie、授权头、用户隐私和其他敏感信息。

## 禁止

- 不把多个问题合成一句笼统结论。
- 不把高疑似、推测或待确认写成已确认事实。
- 不用技术调用链、方法名或日志关键词冒充用户复现路径。
- 不生成假的产品截图，不用装饰性圈选代替证据关系。
- 不因追求视觉效果删掉会改变决策的限制条件。
